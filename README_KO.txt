USB 복원 진단 도구 v1.0 — Windows 10/11, Windows PowerShell 5.1

목적
프로그램이 '이미 쓰여 있음'을 판단하는 단계와 USB 통신 방식의 단서를 수집합니다.
응답 모사/복호화 도구의 첫 진단 단계이며, 이 버전은 응답 변경이나 장비 쓰기를 하지 않습니다.
기존 프로그램을 직접 조작하면 그 프로그램의 정상 쓰기 동작은 발생할 수 있습니다.

실행
1. ZIP을 쓰기 가능한 로컬 폴더에 전부 압축 해제합니다.
2. USB 캡처에는 Wireshark의 TShark 구성 요소와 USBPcap이 필요합니다.
   공식 다운로드: https://www.wireshark.org/download.html
   USBPcap: https://desowin.org/usbpcap/
   설치 시 USBPcap을 포함하고, 재부팅을 요청하면 재부팅합니다.
   도구는 어떤 드라이버도 자동 설치하지 않습니다. 설치 없이 정보 수집만 할 수도 있습니다.
3. 장비를 연결하고 Run.cmd를 우클릭하여 '관리자 권한으로 실행'합니다.
   Python 설치는 필요 없습니다. 시스템 실행 정책은 변경하지 않습니다.
   조직 정책이 스크립트 실행을 차단하면 해당 오류를 알려 주세요.
4. 파일 선택 창에서 원래 장비에 쓰던 프로그램 EXE를 선택합니다. 자동 실행하지 않습니다.
5. 암호화 입력 파일 정보 수집은 y를 입력하여 선택할 수 있습니다. Enter면 건너뜁니다.
6. USBPcap 인터페이스 번호를 선택합니다. 잘 모르겠으면 Enter로 건너뛰어도 됩니다.
   여러 USBPcap이 있으면 Wireshark의 캡처 옵션에서 USBPcap 설정(톱니바퀴)의
   장비 목록을 확인해 대상 장비가 연결된 root hub를 선택합니다.
   모르는 번호를 무작위로 고르면 대상 통신이 누락될 수 있습니다.
7. 캡처 시간은 기본 45초, 10~300초로 설정할 수 있습니다.
8. 준비 후 Enter를 누릅니다. 캡처 시작 안내가 나오면 원래 프로그램을 직접 실행하고
   파일 선택 → 평소 쓰기 동작 → '이미 쓰여 있음' 메시지를 한 번 재현합니다.
   캡처는 시간이 지나면 자동 종료됩니다. 이 동안 수집기 창을 닫지 마세요.
9. 가능하면 원래 프로그램을 켜 둔 상태로, 메시지 원문과 발생 시점을 입력합니다.
10. 탐색기에 선택되어 표시되는 results_날짜_시간_식별자.zip을 대화에 첨부하세요.

보내 줄 것
- 우선 results_....zip 하나면 됩니다. 프로그램 본체나 전체 암호화 파일은 포함하지 않습니다.
- 파일 첨부가 어려우면 SUMMARY.txt, issues.json, observations.json,
  api_name_hints.json, neighbor_files.json을 보내세요.
- USB 응답 바이트 분석에는 capture.pcapng가 필요합니다.
- 캡처 실패 시에도 ZIP을 보내면 다음 해결 단계를 안내할 수 있습니다.

수집 범위
프로그램 이름/버전/SHA256, 같은 폴더 바로 아래 EXE/DLL/config 이름과 크기,
EXE 내부의 사전에 지정된 통신 API 이름 존재 여부, 실행 중인 동일 이름 프로세스의
모듈 이름, 연결된 USB/HID 장비 및 드라이버 정보, 선택한 USB root hub의 통신,
선택 시 입력 파일의 이름/크기/SHA256/앞 64바이트, 직접 입력한 관찰 내용.
EXE/DLL/config 원문, 암호화 파일 전체, 임의의 파일이나 프로세스 메모리는 수집하지 않습니다.
네트워크 업로드는 없으며 결과는 로컬 폴더에만 생성됩니다.
USB 캡처에는 실제 데이터와 동일 root hub의 다른 장비 통신이 포함될 수 있고,
장비 ID에는 일련번호가 포함될 수 있습니다. 필요 없는 USB 장비는 분리해 두세요.

한계/다음 단계
패킷 개수가 0이 아니어도 대상 장비 통신이 포함되었다는 보장은 없습니다.
usb_frames.csv는 프레임 요약이며, 페이로드는 capture.pcapng에 보존됩니다.
API 이름 검색은 import table 분석이 아니며, 이름이 없다고 해당 API를 안 쓰는 것은 아닙니다.
복호화가 PC/장비 중 어디서 되는지 이 단계만으로 확정할 수는 없습니다.
결과를 바탕으로 상태 조회/응답/중단 지점을 식별한 뒤 응답 모사 또는 송신 버퍼 추출을 설계합니다.

검증 상태
제공 환경은 Linux이므로 실제 Windows 장비/드라이버에서의 실행은 검증하지 못했습니다.
Windows 실행 오류도 결과 ZIP의 로그에 가능한 한 보존하도록 만들었습니다.
